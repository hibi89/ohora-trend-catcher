# OHORA n8n → Google Sheets 연동 명세

상태: 설계 명세만 작성됨. 기존 n8n 핵심 자동화가 완성된 뒤 구현한다.

## 목적과 데이터 경계

최종 흐름은 `Meta API A/B/C → P6 수집 엔진 → SQLite/RAW → n8n → Google Sheets`다.

- P6 SQLite/RAW는 전체 원본, 수집 이력, 요청/응답 증거, 커서와 수집 완전성의 기준 저장소다. Sheets로 옮기거나 요약하더라도 이 역할을 바꾸지 않는다.
- Google Sheets는 팀 공유와 분석을 위한 파생 출력이다. 수동 편집·삭제나 동기화 실패가 P6 수집 또는 RAW 영속성에 영향을 주면 안 된다.
- n8n은 P6가 검증하고 durable receipt로 확정한 결과만 읽는다. Meta 인증정보, 커서, 전체 RAW 응답 payload는 Sheets로 보내지 않는다.
- 이 연동은 기존 n8n 핵심 수집 orchestration의 운영 검증 이후 별도 작업으로 진행한다. P6 동결 설계 및 P6 수집기 구현을 변경하지 않는다.

## 출력 행 계약

헤더와 필드 순서는 다음으로 고정한다. 스키마 버전을 별도 메타데이터 행 또는 설정 값으로 기록한다.

| 열 | 정의 |
| --- | --- |
| `post_id` | 게시물의 안정적인 고유 키. 빈 값은 거부한다. |
| `country` | 해당 계정에 매핑된 국가 코드/값. 계정 기준 원본이 검증되지 않으면 빈 값으로 둔다. |
| `post_date` | 원본에서 확인된 게시 시각(ISO 8601, timezone 포함 권장). |
| `collected_at` | durable receipt/관측 이력의 수집 시각(ISO 8601, timezone 포함). |
| `likes` | 검증된 좋아요 수. 미수집/누락은 빈 값으로 두며 0으로 대체하지 않는다. |
| `comments` | 검증된 댓글 수. 미수집/누락은 빈 값으로 둔다. |
| `reels_views` | 실제 검증된 조회수 필드가 있을 때만 기록한다. 미디어 유형만으로 Reels나 조회수를 추론하지 않는다. |
| `post_url` | 검증된 게시물 URL. 원본에서 제공되지 않으면 빈 값으로 둔다. |

RAW payload 전체나 토큰, 사용자 개인정보, 내부 DB 경로/커서, 오류 응답 본문을 출력하지 않는다. 공유 시트는 최소 권한으로 공유하고 링크 접근 범위를 별도로 검토한다.

## 증분 동기화 및 재실행 안전성

1. n8n은 SQLite의 읽기 전용 연결 또는 P6가 제공하는 검증된 read API/view를 통해 내보내기 대상과 진행 상태를 읽는다. 대상은 durable receipt가 확정된 게시물 관측만 포함한다.
2. 증분 기준은 단조 증가하는 durable receipt/observation 식별자와 해당 출력 대상의 체크포인트다. `post_id` 단독 워터마크를 쓰지 않는다. 늦게 도착한 관측도 빠뜨리지 않도록 receipt 순서로 페이지 조회한다.
3. 시트의 분석 행은 `post_id`를 idempotency key로 사용하며, 재실행은 기존 행을 갱신(upsert)한다. Google Sheets가 키 기반 upsert를 보장한다고 가정하지 말고, 구현 시 읽기-인덱스-배치 갱신/추가 또는 동등한 안전한 어댑터를 선택하고 동시 실행을 직렬화한다.
4. 같은 게시물의 새 수집 관측을 보존해야 하는 분석 방식이면 게시물 요약 시트와 관측 이력 시트를 분리한다. 요약 시트는 post_id당 한 행, 이력 시트는 durable receipt/observation ID당 한 행을 사용한다. 기존 저장소의 관측 이력을 덮어쓰거나 제거하지 않는다.
5. 체크포인트는 시트 쓰기가 성공하고 반영을 확인한 뒤에만 앞으로 이동한다. 부분 실패 시 같은 배치를 재실행해도 같은 행을 갱신하며, 이미 성공한 행은 중복 추가하지 않는다.
6. 제한 응답/일시 오류는 제한된 지수 backoff로 재시도한다. 재시도 소진 시 체크포인트를 보존하고 실패 배치와 안전한 진단 메타데이터를 dead-letter/재시도 큐에 남긴다. 재시도는 명시적이고 관측 가능해야 한다.
7. 시트 동기화는 P6 수집 실행과 분리된 n8n 작업으로 운용한다. Sheets 장애 시 P6/SQLite/RAW 수집을 중단하지 않고, 미동기화 watermark와 경고를 유지한다. 복구 후 누락 구간을 재생한다.
8. 정기 reconciliation은 SQLite의 대상 건수/ID 범위와 시트의 동기화 상태를 비교한다. 삭제된 시트 행은 원본 삭제로 취급하지 않으며, 자동으로 RAW를 수정하지 않는다.

## 완료 전 검증 기준

- mock SQLite/read API와 mock Sheets adapter를 이용해 신규 행, 재실행, 부분 성공, 중복 입력, 늦게 도착한 관측, Sheets timeout/quota 오류, 체크포인트 보류, 재생, 시트 행 수동 삭제를 오프라인 검증한다.
- P6 수집 성공 여부와 Sheets export 상태를 별도로 기록한다. Sheets 실패는 `export_pending`/동등 상태와 경고로 표현하고 수집 성공을 되돌리지 않는다.
- 실제 API 인증/Google 계정 연결 및 대상 시트 식별은 구현·연결 단계에서 요청한다. Credential은 n8n credential store에만 둔다. 토큰·서비스 계정 키·스프레드시트 ID는 Git, workflow JSON, 로그에 넣지 않는다.
- 운영 연결 전 mock 검증, 중복 방지, 체크포인트/재생, 권한 범위, 경고 전달, 수동 재처리 절차를 확인한다. 실제 Google 인증이나 운영 시트 변경은 별도 연결 시점에 수행한다.

## 현재 미완료

아직 n8n 노드, SQLite export view/API, 체크포인트 저장소, Google credential, 대상 spreadsheet, 실제 연결 테스트는 구현·설정되지 않았다. 이 문서는 연동 설계 기준이며 실제 수집 또는 Sheets 동기화 성공의 증거가 아니다.
