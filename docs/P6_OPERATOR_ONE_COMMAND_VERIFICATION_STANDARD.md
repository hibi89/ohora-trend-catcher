# P6 운영·검수 단일 명령 표준 (필수)

## 목적
코드 작성자는 운영자가 로그를 붙여넣고 원인을 추리하도록 만들지 않는다. **실제 실행 전에 단일 명령으로 상태·원인·복구 조건·다음 행동을 확인**할 수 있어야 한다. 이 문서는 개발/검수 수용 기준이며, 현재 단일 명령 기능이 이미 구현됐다는 뜻이 아니다.

## 개발자 의무
1. 새 기능 또는 장애 수정 시 같은 변경에서 성공/실패/재시작/쿨다운/부분완료 검증을 추가한다. 검수 스크립트와 실제 엔진의 판단 규칙을 공유하거나 일치성을 회귀 테스트한다. 별도 수작업 SQL 추리 금지.
2. 단일 읽기 전용 명령 `./p50.ps1 doctor` (목표 인터페이스; 구현 전까지 사용 금지)으로 기존 coordinator.sqlite, RAW 영수증, 페이지 커서/선행 의존성, API A/B/C lane 상태, 50계정/150페이지 진행률을 종합 진단한다. 로컬 DB가 없으면 생성하지 않는다.
3. 결과는 **사람이 읽는 요약 + 구조화된 JSON**으로 출력한다. 필수 필드: schema_version, workspace_date, total_accounts, first_page_accounts, total_pages, committed_pages, remaining_pages, per_lane{halted,reason,ready_at,ready_jobs,blocked_jobs,usage_percent,usage_checked_at}, blockers{type,affected_jobs,explanation}, next_safe_action, completion, exit_code. 원격 API 사용량을 확인하지 않았으면 `unknown`으로 표기하고 절대 추정하지 않는다.
4. **실제 호출 없이 진단하는 기본 모드**와 명시 승인 후 최소 호출로 사용량을 확인하는 모드를 구분한다. Meta 실호출/잠금 해제/수집은 승인 플래그 없이는 불가하다.
5. 오류마다 `왜 중단됐는가 / 자동 재개 조건 / 운영자가 해야 할 행동 / 재시도 가능한 시각`을 출력한다. `no_ready_work`를 미완료 성공으로 보고하지 않는다. 같은 오류를 반복하면 기존 오류 기록과 비교해 새로운 원인 없이는 동일 진단만 추가하지 않는다.
6. 가능 작업이 0이면 `대기`인지 `구조적 교착`인지 구별한다. 특히 B가 막혀 A/C가 선행 페이지를 기다리는 상황을 숫자로 설명한다. 쿨다운 종료 전에는 사용량이 1%라도 임의 해제하지 않는다.
7. 새로 실행할 수집 명령도 하나로 통합한다(목표: `./p50.ps1 run -Live`). 진단→승인된 안전 검증→가능한 페이지 수집→저장 증거 검증→최종 보고. **자동 복구는 기존 85% 한도, 쿨다운, 승인, 직렬 잠금, 고정 lane 정책을 준수할 때만** 허용한다.
8. 테스트는 mock/임시 DB 기반 오프라인 테스트를 기본으로 하고, 실호출 성공을 테스트 통과로 가장하지 않는다. Windows PowerShell에서 실제 한 줄 명령과 출력 예시를 검증한다.

## 불변 조건
기존 RAW/Capture/SQLite 관측 이력, 수집 영수증, 커서, API A/B/C 고정 배정, limit=4, 3페이지/계정, 85% 중단, 직렬 잠금, 실호출 승인, main 병합 승인 규칙을 유지한다. 이 문서는 구조 변경을 승인하지 않는다. 고정 배정 완화 등은 별도 설계/승인 후 진행한다.

## 완료 판정
- 단일 명령 실행 결과만으로 53/150 같은 부분완료와 각 레인의 실제 차단 이유를 설명할 수 있음.
- 성공/대기/운영자 조치/오류를 구분하는 종료 코드와 기계 판독 가능한 출력.
- 재실행 시 기존 영수증/완료 페이지를 중복 저장하지 않음.
- 50계정 × 3페이지 검증과 테스트 결과, 미검증 사항을 명시.
- 검수자가 추가 SQL, 개별 파이썬 명령, 채팅 추론 없이 다음 행동을 결정할 수 있음.

## 현재 관측 사례 (2026-10-23, 사용자 제공)
53/150 페이지 완료, 97 잔여. A: done 18/waiting_predecessor 32, B: done 1/usage_limit hold/eligible 49, C: done 34/waiting_predecessor 16. B Meta 사용량 1% 검증됐으나 released=false. 이 사례를 회귀 테스트에 포함한다. `ready_at`과 현재 시각, reason을 비교해 조건 불충족을 정확히 표시한다. 실호출과 로컬 Windows 테스트는 본 문서 작성 과정에서 수행하지 않았다.
